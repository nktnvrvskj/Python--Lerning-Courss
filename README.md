# Менеджер задач v0.2.0

Учебный проект курса Python: приложение для управления задачами на `tkinter`,
переработанное в модульную ООП-архитектуру из четырёх классов.

**Версия:** 0.2.0 · **Стек:** Python 3.10+, tkinter, JSON · **GUI:** только через
компоненты `App*`.

---

## Что было сделано в 0.2.0

- Приложение разделено на четыре класса с чёткими зонами ответственности:
  `Task`, `StorageManager`, `Interface`, `TaskManager`.
- Реализован полный CRUD: создание, редактирование, удаление и переключение
  статуса «выполнено».
- Логика полностью отделена от интерфейса: `TaskManager` не импортирует
  `tkinter` и общается с окном только через методы `Interface`.
- UI собран из наследников tk-виджетов: `AppFrame`, `AppLabel`, `AppEntry`,
  `AppText`, `AppButton`, `AppListbox`, `AppScrollbar`.
- Простой светлый интерфейс в две колонки: слева список, справа карточка
  выбранной задачи с описанием, автором, статусом, датой и ID.
- `StorageManager` сохраняет задачи в JSON атомарно (через временный файл),
  восстанавливается после повреждённого JSON и понимает старый формат v0.1.0.
- Добавлены валидация ввода, обработка ошибок и тесты (модель, хранилище,
  бизнес-логика и дымовой тест реального окна).

## Архитектура

```text
                    main.py
                       │ создаёт и запускает
                       ▼
                  TaskManager  ──────────────┐
                  (фасад, CRUD)               │
                    │            │            │
                    ▼            ▼            ▼
                 Task      StorageManager   Interface
              (данные)      (JSON-файл)     (tkinter)
                    ▲            │            │
                    └────────────┘            ▼
                         to_dict/from_dict   AppFrame, AppLabel,
                                             AppEntry, AppText,
                                             AppButton, AppListbox
```

| Класс | Файл | Ответственность |
|:--|:--|:--|
| **`Task`** | [src/task.py](src/task.py) | Поля `id`, `title`, `description`, `status`, `author`, `created_at`; `to_dict()` / `from_dict()`; не знает про JSON и tkinter |
| **`StorageManager`** | [src/storage_manager.py](src/storage_manager.py) | `load`, `save`, `add`, `update`, `delete`; уникальные id; атомарная запись JSON; восстановление после повреждённого файла |
| **`Interface`** | [src/ui/Interface.py](src/ui/Interface.py) | `build`, `get_input`, `set_input`, `clear_input`, `show_tasks`, `show_task_details`, `show_message`, `show_warning`, `ask_confirm`, `get_selected_index`; использует только `App*` |
| **`TaskManager`** | [src/task_manager.py](src/task_manager.py) | `create_task`, `edit_task`, `delete_task`, `toggle_status`, `refresh`, `run`; связывает модель, хранилище и интерфейс |

Ключевое правило: **зависимости идут в одну сторону**. `Task` не импортирует
ничего из проекта, `StorageManager` знает только `Task`, `Interface` не знает
про задачи вообще, а `TaskManager` — единственный, кто знает всех.

### Поток одного действия

1. Пользователь заполняет поля и нажимает **«Сохранить»**.
2. `AppButton` вызывает действие `save` из `Interface.actions`.
3. `TaskManager.save_task()` решает: выделена задача — `edit_task()`, нет —
   `create_task()`.
4. `TaskManager` читает `Interface.get_input()`, валидирует данные и создаёт
   `Task`.
5. `StorageManager.add()` / `update()` записывает JSON.
6. `TaskManager.refresh()` перечитывает файл, обновляет список и карточку
   подробностей через `Interface.show_tasks()` / `show_task_details()`.

Подробный разбор каждого класса, методов и вопросов для защиты — в
[documents/ARCHITECTURE.md](documents/ARCHITECTURE.md).

Клик по задаче слева сразу показывает справа её описание, автора, статус,
дату создания и ID и заполняет форму для редактирования. После сохранения
задача остаётся выбранной, поэтому кнопка «Сохранить» сразу редактирует её,
а «＋ Новая» очищает форму и снимает выделение.

## Запуск

Нужен Python 3.10+ с модулем `tkinter` (в Windows и macOS он входит в
установщик Python; в Linux — пакет `python3-tk`).

```bash
# из корня репозитория
python3 src/main.py
```

Можно запустить и из папки `src`:

```bash
cd src
python3 main.py
```

Внешние библиотеки не требуются. Файл `src/task.json` создастся сам.

### Проверка сохранения

1. Создайте две-три задачи.
2. Отметьте одну кнопкой **«Готово»**.
3. Нажмите **«Выход»** и запустите приложение снова — задачи и статусы
   останутся на месте.

## Как пользоваться

| Кнопка / клавиша | Действие |
|:--|:--|
| **＋ Новая** | Очистить форму и снять выделение, чтобы ввести новую задачу |
| **Сохранить** | Создать новую задачу (если ничего не выбрано) или сохранить изменения выбранной |
| **Готово** | Переключить статус выбранной задачи |
| **Удалить** | Удалить выбранную задачу после подтверждения |
| **Выход** | Закрыть приложение |
| Клик по задаче | Показать описание, автора, статус, дату и ID справа, загрузить данные в форму |
| `Enter` / `Ctrl+S` | Сохранить |
| `Ctrl+N` | Новая задача |
| `F5` | Перечитать список с диска |
| `Esc` | Выход |
| `Delete` (в списке) | Удалить выбранную задачу |

Валидация: название обязательно, не длиннее 120 символов; описание — до 500,
автор — до 60. Описание редактируется в многострочном поле и переносится по
словам. Ошибки показываются диалогом, успешные действия — в статус-строке
внизу.

## Формат данных

`src/task.json` — массив объектов:

```json
[
  {
    "id": 1,
    "title": "Сдать модуль 2",
    "description": "ООП и модульная архитектура",
    "status": false,
    "author": "Никита",
    "created_at": "2026-11-12T21:15:00"
  },
  {
    "id": 2,
    "title": "Подготовить документацию",
    "description": "README и схема классов",
    "status": true,
    "author": "Никита",
    "created_at": "2026-11-12T21:15:00"
  }
]
```

Старый формат v0.1.0 (`[{"name": "..."}]`) читается автоматически: поле `name`
становится названием, после первой загрузки файл перезаписывается в новом
виде. Битый JSON сохраняется рядом как `task.json.broken`, приложение
запускается с пустым списком.
